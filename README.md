# protestware-check

**Static source-code and software-supply-chain triage tool** / **Статический анализатор признаков protestware и рисков цепочки поставки ПО**.

`protestware-check` (версия кода **1.1.0**, ветка `main`) анализирует локальные каталоги и GitHub-репозитории **без выполнения проверяемого кода**. Находки предназначены для расследования специалистом по ИБ: **политические высказывания, географические ограничения и присутствие в сторонних списках сами по себе не доказывают вредоносность**.

> **Статус на 09.11.2026:** репозиторий публичный; GitHub Releases отсутствуют. Версия в коде не означает опубликованный релиз. Порядок выпуска описан в [контрольном списке](docs/RELEASE_CHECKLIST.md).

## Возможности

| Область | Что проверяется |
| --- | --- |
| Protestware | Проверки страны/геолокации рядом с сетевыми и файловыми действиями; ограниченное отслеживание условий и вызовов |
| Сетевые вызовы | Неожиданные внешние URL, динамические адреса, некоторые сценарии массированных запросов (`NETWORK_FLOOD`) |
| Файловые операции и исполнение | Удаление, запись, запуск процессов, динамическое исполнение и API геолокации |
| Обфускация | Кодирование и характерные сочетания техник JS/TS (`OBFUSCATED_JS`) |
| AST / taint | Python; Tree-sitter для Go, C#, JS/TS, C/C++, SQL, HTML, CSS, SCSS, Less; ограниченный структурный разбор `.sass` |
| Зависимости | Lock-файлы npm, Python, Cargo, Composer, Go, NuGet; при необходимости — метаданные официальных реестров |
| Внешние источники | `toxic-repos` / `black-mark` (контекст), дополнительные отчёты [OpenSSF/OSV и GitHub malware advisories](docs/MALWARE_INTELLIGENCE.md) по **точным версиям пакетов** |
| Отчётность | Текст, JSON, SARIF 2.1.0, CycloneDX JSON 1.6 |

**Область применимости:** синтаксический разбор не означает полноценный CFG/SSA. Межфункциональный анализ ограничен одним файлом; не охватывает все перегрузки, макросы, динамические вызовы, контекст сборки и пути через сторонние компоненты. Для C/C++ применяется ограниченный внут­рифайловый граф вызовов. Отрицательный результат — **не гарантия безопасности**.

## Быстрый старт

Требования: **Python 3.11+**, Git (для клонирования самого сканера) и интернет для первоначальной установки зависимостей/грамматик и выбранных удалённых функций.

```bash
git clone https://github.com/ruslancotcaev9-cyber/protestware_check.git
cd protestware_check
python3 -m venv .venv
source .venv/bin/activate          # Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r requirements-ast.txt -r requirements-resolver.txt
python -c 'from tree_sitter_language_pack import download; download(["go","csharp","javascript","typescript","tsx","sql","html","css","scss","less","c","cpp"])'
```

Без необязательных пакетов доступны базовые эвристики и встроенный Python AST. Tree-sitter использует только заранее загруженные грамматики: при их отсутствии `auto` предупреждает о неполноте, `required` возвращает код 2.

`required` проверяет доступность и успешность AST-разбора только для языков с поддерживаемым парсером. Он не требует AST для всех файлов проекта: например, каталог только с `.rs` может вернуть код 0 при `ast.complete=false`. Для оценки покрытия учитывайте [поддерживаемые форматы и поля полноты](docs/USER_GUIDE.md#5-интерпретация-отчётов-и-ci).

```bash
# Локальная проверка, без внешних списков; только зафиксированные зависимости
python protestware_check.py --path ../my-project --ast-mode auto \
  --dependencies lock --format json --output findings.json

# Проверка конкретного дерева GitHub; только чтение через API
python protestware_check.py --repo fmtlib/fmt --ref YOUR_COMMIT_SHA \
  --ast-mode auto --watchlists live --format sarif --output findings.sarif

# SBOM
python protestware_check.py --path ../my-project --dependencies lock \
  --format cyclonedx --output sbom.cdx.json
```

**Коды выхода:** `0` — риск ниже порога и нет ошибки, требующей кода 2; `1` — достигнут `--fail-on`; `2` — ошибка, неполное чтение исходников, превышение общего бюджета, отсутствие требуемого AST либо неполнота при `--dependency-strict` / `--malware-strict`. Код 2 имеет приоритет перед порогом риска. По умолчанию: `--fail-on high`, `--watchlists off`, `--malware-intel off`, `--dependencies lock`, `--ast-mode auto`. Код 0 не доказывает полное покрытие: проверяйте поля полноты в отчёте.

Лимиты: `--max-bytes 1000000` на файл, `--max-files 10000`, `--max-total-bytes 100000000` на декодированный текст. Отчёты сохраняйте вне проверяемого каталога: запись атомарная, конечные символические ссылки и перезапись существующих исходных файлов запрещены. Для полностью локального запуска используйте `--path`, `--dependencies lock`, `--watchlists off` и `--malware-intel off` после подготовки окружения.

## Новые источники сведений о вредоносных пакетах (v1.1.0)

```bash
# Только явный opt-in: запросы к OSV.dev и GitHub Advisory Database
python protestware_check.py --path ../my-project --dependencies lock \
  --malware-intel both --malware-strict --format json --output findings.json
```

OSV/OpenSSF и GitHub частично дублируют записи; единый `MALWARE_ADVISORY` включает ID, ссылки и происхождение. Без точной версии, при неподтверждённом соответствии источника публичному реестру или недоступности API охват будет частичным. Git, локальные и частные источники пакетов не подменяются публичными координатами. `--malware-strict` завершает неполную проверку с кодом 2. Исходный код проверяемых проектов не выполняется. См. [подробную методологию и безопасность интеграций](docs/MALWARE_INTELLIGENCE.md).

Исчерпание лимитов AST/taint теперь отражается в предупреждениях и `ast.complete=false`; `--ast-mode required` возвращает код 2. Для Go сканер учитывает `go.mod`, `indirect` и `replace`: старые версии из `go.sum` не выдаются за текущие зависимости. Полный выбранный граф сборки Go статически не вычисляется, поэтому модуль с требованиями остаётся неполным для `--dependency-strict`.

## Работа с находками

Сначала разберите `high` по файлу и строке, затем проверьте путь данных, достижимость, назначение компонента и влияние на пользователей. Отдельно оценивайте внешние списки и политический текст: эти индикаторы **не должны быть единственным основанием для признания пакета вредоносным**.

При анализе недоверенного кода запрещается запускать его сборочные скрипты и зависимости вне изолированной среды. Сам сканер не выполняет проверяемый код, но может делать HTTPS-запросы к GitHub и официальным реестрам, если эти режимы выбраны. JSON/SARIF-отчёты могут содержать фрагменты приватных исходников — контролируйте доступ.
