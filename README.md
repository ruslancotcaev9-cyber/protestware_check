# protestware-check

Статический эвристический анализатор репозиториев на индикаторы **protestware** и рискованных действий в цепочке поставки ПО. Написан на Python 3.10+, не требует сторонних пакетов и **никогда не выполняет** код анализируемого проекта.

> **Важно:** найденная политическая формулировка, включая критику России, — не вредоносное ПО и не доказательство вредоносного намерения. Политические сигналы выделяются в категорию `context` со степенью `info` и **не влияют** на технический риск. Технические находки также являются поводом для ручной проверки, а не вердиктом о вредоносности.

## Возможности

| Правило | Что ищет | Уровень |
| --- | --- | --- |
| `POLITICAL_RU` | явно выраженные политические формулировки, касающиеся РФ (в README, документации, коде) | `info` |
| `GEO_DISCOVERY` | вызовы интерфейсов геолокации / GeoIP | `low` |
| `GEO_TARGET` | проверки географических переменных в условии, содержащем `RU`/`RUS`/`BY`/`BLR`, названия стран | `medium` |
| `NET_EXTERNAL` | вызов сетевой функции с доменом вне разрешённого списка | `medium` |
| `NET_DYNAMIC` | сетевой вызов, когда адрес формируется динамически либо не найден рядом | `low` |
| `NET_GEO_API` | запрос к известному IP-геолокационному сервису | `medium` |
| `FS_DELETE` | функции удаления файлов/каталогов, команды удаления | `medium` |
| `FS_WRITE` | функции записи/перемещения файлов | `low` |
| `OBF_DECODE_EXEC` | выполнение декодируемого кода, например `eval(atob(...))` | `high` |
| `OBF_DYNAMIC_EXEC` | динамическое выполнение `eval`/`exec` | `medium` |
| `OBF_ENCODING` | возможное сокрытие данных (`atob`, `fromCharCode`, длинные строки Base64) | `low` |
| `GEO_ACTION` | географическая проверка близко (до 15 строк) к сетевому/файловому действию | `high` |

Правило `GEO_ACTION` использует **близость строк**, не доказанный control-flow или data-flow. Оно подвержено ложным срабатываниям. Сетевые адреса сравниваются с пользовательским allowlist; без него любые явные внешние домены являются объектом ревью. Неизвестность домена **не означает** вредоносность. Политические ключевые фразы предназначены для выявления контекста и не служат основанием для блокировки пользователей или авторов.

## Быстрый старт

```bash
# Проверка текущего каталога
python3 protestware_check.py --path .

# Публичный GitHub-репозиторий, без git clone
python3 protestware_check.py --repo owner/repository --format json

# Приватный репозиторий: токен только через переменную окружения
export GITHUB_TOKEN="<token-with-repository-read-access>"
python3 protestware_check.py --repo https://github.com/owner/repository --ref main

# Ожидаемые API и каталог сборки, порог остановки CI
python3 protestware_check.py --path ./source \
  --allow-domain api.example.org --exclude 'generated/*' --fail-on medium
```

Опции CLI: `--path DIR` (по умолчанию текущий каталог) или `--repo OWNER/REPO` (взаимоисключающие), `--ref BRANCH_OR_SHA`, `--format text|json`, `--fail-on low|medium|high` (по умолчанию `high`), `--allow-domain DOMAIN` (повторяемая опция, разрешены субдомены), `--exclude GLOB` (повторяемая опция), `--max-bytes N` (по умолчанию 1 000 000), `--political-terms-file FILE` (UTF-8, одна буквальная фраза в строке, `#` в начале строки — комментарий).

### Выходные коды

- `0`: анализ завершён, технический риск ниже порога `--fail-on` (или технических находок нет).
- `1`: анализ завершён и порог технического риска достигнут.
- `2`: ошибка параметров, чтения или GitHub API. При `truncated=true` у GitHub Tree API анализ прерывается, неполный отчёт не выдаётся.

### JSON-отчёт

```json
{
  "tool": "protestware-check",
  "version": "0.1.0",
  "source": "owner/repository",
  "files_scanned": 1,
  "risk": "medium",
  "summary": {"info": 0, "low": 0, "medium": 1, "high": 0},
  "findings": [
    {"rule": "FS_DELETE", "category": "filesystem", "severity": "medium",
     "file": "src/mod.py", "line": 2, "evidence": "shutil.rmtree(path)",
     "message": "Потенциально удаляющая операция с файловой системой"}
  ],
  "warnings": []
}
```

Этот фрагмент иллюстрирует **формат**; итоговые значения `summary` и `risk` вычисляются из реальных находок при запуске.

## Архитектура и безопасность

1. Локальная проверка читает только обычные файлы: символьные ссылки и системные каталоги (`.git`, `node_modules`, `.venv`, `dist` и т. д.) пропускаются. Исполняемых файлов, тестов, `npm install` или `pip install` проверяемого проекта не запускает.
2. Удалённая проверка обращается к GitHub REST API (`/repos`, рекурсивное дерево и Git blobs) по HTTPS. Для приватных репозиториев нужен `GITHUB_TOKEN` с правом чтения Contents. Токен не включается в отчёт и не печатается при HTTP-ошибках.
3. Ограничены форматы текстовых файлов, максимальный размер одного файла, и исключены сгенерированные артефакты по умолчанию. Большие файлы приводят к предупреждениям, **не** проверяются. Символьные ссылки в Git tree не обходятся.
4. Не производит сетевых запросов к доменам, найденным в исходниках. Не декодирует и не выполняет подозрительные полезные нагрузки.
5. Для Python строки и комментарии маскируются при технической проверке, но остаются доступными контекстному поиску политических фраз. Код проверяется шаблонами и небольшим корреляционным правилом. Это triage-инструмент, а не полноценные AST/taint-анализ, песочница или гарантия отсутствия вредоносного кода.

**Ограничения:** многострочные и вычисляемые обращения, непрямые вызовы, обфускация вне описанных шаблонов, компилированные файлы, vendored/minified пакеты и пропущенные файлы могут остаться незамеченными. Информация об истории коммитов, авторах, GitHub Issues и README из других веток не анализируется. `GEO_ACTION` не доказывает связь операций. Негативная политическая риторика не приравнивается к атаке.

## Рекомендованный процесс ревью

Проверяйте `high` в первую очередь: изучите окружающую функцию, условия выполнения, целевые пути удаления, эксфильтрацию и необходимость вызова. Для `medium` сопоставьте назначение библиотеки с её сетевыми и файловыми операциями. Подтверждайте нетипичные домены из независимых источников и добавляйте заведомо легитимные в `--allow-domain`. Результаты могут содержать строки исходного кода, поэтому не публикуйте отчёты приватных проектов.
