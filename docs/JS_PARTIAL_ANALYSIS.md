# Уточнение частичного анализа JS/TS в 1.5.1

[Поддержка и бюджеты](JS_MODULE_ANALYSIS.md) · [Результаты 1.5.1](VALIDATION_1_5_1.md) · [Предыдущие результаты](VALIDATION_1_5_0.md).
Версия остаётся unreleased. Код целевых проектов не исполняется.

## Сводки рекурсивных вызовов

Ранее повторный вход в контекст функции обрывал анализ с диагностикой рекурсии.
Теперь контексты и зависимости между ними обрабатываются рабочей очередью.
Сводка содержит только уже найденные нативные удаляющие эффекты и их трассы.
Новый эффект повторно ставит вызывающие контексты в очередь; проход заканчивается,
когда сводки перестают изменяться. Рекурсивная компонента без операции удаления
стабилизируется пустой. Она не объявляется безопасной или завершающейся.

Аргументы разных вызовов сохраняются в разных контекстах: переданный rmSync
не должен появляться в соседнем вызове с безопасной callback-функцией.
Поддержка ограничена ранее моделируемыми статическими вызовами/параметрами;
фабрики функций, динамическая диспетчеризация и полноценный CFG не добавлены.

Работа ограничена 2 048 контекстами, 40 000 обработанными событиями сводок и
общим лимитом разрешения значений. Трассы ограничены 24 шагами в кеше и отчёте,
с сохранением конечной операции. При исчерпании лимита уже найденные наблюдения
сохраняются, но анализ остаётся partial; required возвращает 2.

## Spread и неизвестные свойства

Ранее любой spread делал весь объект и модуль неполными. Теперь известные
локальные свойства копируются в порядке объявления. Для неизвестного spread
или вычисляемого ключа сохраняется неизвестное значение возможных перекрытий.
Позднее явное свойство восстанавливает известную идентичность только этого ключа.

| Пример | Поведение |
|---|---|
| rmSync(path, {...options, force: true}) | Неизвестные параметры не меняют известную идентичность самого rmSync |
| const unused = {...unknown} | Не влияет на полноту без чтения соответствующих свойств при разрешении вызовов |
| {...unknown, erase: rmSync} | Поздний erase известен |
| {erase: rmSync, ...unknown}; obj.erase(path) | Подмена возможна; нативная идентичность не доказана, partial |
| {erase: rmSync, ...safeObject} | Используется скопированное значение erase из известного safeObject |

Это ограниченное статическое моделирование свойств. Не реализованы произвольные
getter/proxy-эффекты, типизация, прототипы и все способы изменения объектов.
Неизвестное значение не становится доказанным нативным API.

## Поиск сетевого поведения

NETWORK_FLOOD ищет достижимый по статическому графу именованных функций сетевой
вызов из тела неограниченного цикла. Повторные посещения функции не нужны для
этого поиска. Вместо рекурсивного обхода применяется итеративный поиск с набором посещённых
функций и общим на файл бюджетом 80 000 посещений узлов. Наличие пути — сигнал
для ревью, а не доказательство исполнения или злонамеренности.

## Сопоставление с 1.5.0

Тексты, метки, режимы AST и локальные helper-файлы регрессий не изменены.
Сохранены архивы корпусов, журнала и заморозки 1.5.0; равенство входов проверяет тест.
На восьми проектных примерах rimraf остаются четыре обнаружения и четыре
отрицательных результата. Число partial снижено с пяти до двух.
Native, posix и отрицательный opt-arg больше не имеют прежней диагностики.
Windows и move-remove остаются partial: читаемые свойства могут происходить из
неизвестного spread в src/rimraf-move-remove.ts:59 и :143. Диагностика не скрыта.

Это сравнение регрессий на тех же входах, не новая независимая оценка качества.
Два известных пропуска fs-extra, внешние partial других проходов и независимое
человеческое ревью меток остаются отдельными задачами.
