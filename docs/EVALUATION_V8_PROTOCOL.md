## Выборка до результатов

План: **24 целых файла из шести ранее не использованных проектов**, по четыре
на язык; два положительных и два отрицательных для целевой операции.
Отбор вручную по назначению и изучению полного кода; это целевая сбалансированная,
коррелированная выборка, а не случайный или слепой эксперимент.
Названия каталогов задают отправную область поиска, а не запрет на другой
подходящий исходник того же закреплённого проекта.

Все шесть закреплённых лицензий разрешают воспроизведение с сохранением notices;
их точные тексты и хеши входят в набор. У pressly/goose автоматическая GitHub
классификация NOASSERTION; сам закреплённый LICENSE содержит MIT License.

Критерии: исходный полный UTF-8 файл, до 100 000 байт и 1 500 строк.
Тестовые исходники и SQL-примеры допускаются и явно отмечаются. Исключаются
сгенерированные golden-выходы, vendored-код и файлы с неустановленным происхождением.
Исходные пути/импорты не редактируются. Сохраняются оригинальные байты fragment,
Git blob SHA, SHA-256, текст лицензии и её SHA-256; для code допускается только
существующая CRLF-to-LF нормализация harness.

Метка положительная при исполняемом синтаксическом вызове физического удаления
файла/каталога или SQL DROP/TRUNCATE, включая обёртку с установленным назначением.
Для обёртки указывается источник обоснования; неизвестное поведение по одному
имени не считается доказательством. Это возможная операция в файле, не
доказательство достижения пути, обязательного исполнения или malware/protestware.
Отрицательная метка относится только к целевому правилу: удаление поля из
памяти, работа с путями, cache/config без физического удаления и строковые
упоминания сами по себе не дают положительной метки.

Список путей, полный корпус, обоснования, pending-журнал и selection manifest
с хешами прежних входов фиксируются отдельным коммитом **до первого измерения**.
Все метки предлагает ассистент, независимого человеческого ревью нет.
При невозможности плана поправка публикуется до измерения; после результатов
входы/метки не заменяются ради улучшения метрик.

## Запуск и сохранение первого результата

У всех cases ast_mode=auto; вход каждого — один файл, без project helpers.
Другие исходники и import-контекст автоматически не подставляются.
Target-код, его тесты, зависимости, install hooks и сборка не выполняются.

Набор fresh-v8 и его review ledger отдельны от прежних 48/46/56/16 и v7.
CI проверяет привязку журнала и публикует TP/FP/TN/FN, ошибки, partial, backend,
предупреждения и исход каждого файла/языка. Report-only допускает FP/FN,
но не превращает ошибки backend/чтения/валидации в успех.
Исходные JSON, контрольные суммы и ссылки на проверенный код сохраняются.

После просмотра исходов v8 считается использованным. В этой итерации правила
на его результатах не настраиваются. Исправления идут следующим этапом:
с переносом изученных файлов в регрессию и сохранением первой оценки.
Следующая независимая проверка потребует новых входов.

## Пределы выводов

Детектор заморожен до новых входов, но методику и метки предлагает тот же ассистент,
который разрабатывает проект. Pending-журнал не удостоверяет независимость или
личность проверяющего. Для независимой оценки необходим отдельный специалист.
Полный синтаксический проход не гарантирует полную семантику языка; partial и
fallback публикуются независимо от правильного исхода. Нулевая ошибка такого
малого набора не подтверждает безопасность пакетов и не является сертификацией.
