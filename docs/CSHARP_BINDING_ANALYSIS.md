# Разрешение файловых API C#

Актуально для **1.9.0, unreleased**, 18.11.2026.
[Руководство](USER_GUIDE.md) · [Проверка](VALIDATION_1_8_0.md) ·
[Исходные пропуски v7](EVALUATION_V7_2026-11-17.md).

## Область поддержки

При однофайловом анализе сканер использует текст выбранного .cs-файла и заранее
подготовленную грамматику csharp. Исходники не компилируются, не импортируются
и не выполняются. Сборочные свойства, NuGet metadata и Roslyn не вычисляются.
Тип API устанавливается по наблюдаемым using, объявлениям и конструкторам.
Это модель синтаксиса и типов, а не проверка корректности всей C#-программы.

| Входная связь | Поддержка |
|---|---|
| System.IO.File.Delete / Directory.Delete | Полные имена, global::, using System.IO, подходящее namespace, aliases и using static |
| FileInfo / DirectoryInfo | Типизированные поля/параметры/локальные переменные; var из известного значения или new; создание объекта непосредственно перед Delete |
| Поле текущего класса | Короткое имя или this.field; readonly и target-typed new не требуют исполнения конструктора |
| Локальный alias | var alias = knownFile; тип сохраняется при последующих присваиваниях по правилам статически типизированной переменной |
| Вызов | Обычный, ?.Delete, скобки и !; типизированные lambda/foreach параметры |
| Затенение | Наблюдаемые пользовательские типы/параметры/переменные, type parameters, aliases, локальные методы и исходные System.IO-типы не получают native identity по имени |
| Комментарии/строки/method groups | Не считаются вызовами Delete |

Неизвестный dynamic/factory receiver и отсутствующий наблюдаемый using для
File.Delete/Directory.Delete дают явный partial. Global/implicit usings из
других файлов не предполагаются, даже если эти файлы выбраны в том же проекте.
Метод Delete чужого известного типа не становится файловым API.

При полном проходе C# `CS_FS_DELETE` и корреляция `AST_GEO_ACTION` используют
разрешённую связь. Прежние текстовые `CS_FS_DELETE`/`FS_DELETE` заменяются
результатами этой модели. При off, недоступном parser или partial в auto
ограниченный текстовый fallback сохраняется; его нельзя считать доказанной
связью API. Required отказывается от зарегистрированного partial с кодом 2.

## Доказательства и ограничения

Находка содержит resolved_symbol, например System.IO.FileInfo.Delete,
binding_basis=selected-file-type, binding_certainty=possible и dataflow
с шагами type/declaration/construction/sink. Географическая корреляция
сохраняет условие и связь типа. SARIF переносит свойства и codeFlows.
Possible означает потенциальную операцию, а не исполнение пути, точное runtime
значение или признание кода вредоносным. Находки одного правила на одной строке
по-прежнему объединяются по действующему правилу отчётности.

Учитываются только File, Directory, FileInfo и DirectoryInfo. Другие API,
включая FileSystemInfo, произвольные свойства/getters, виртуальный dispatch,
пользовательские преобразования, reflection/dynamic, вывод возвращаемого типа,
полное разрешение partial classes и контекст сборки не моделируются полностью.
Unicode escape в имени и extern alias не разрешаются как компилятором.
Проверка коротких имён консервативна: одноимённое объявление в другом namespace
этого файла может блокировать короткое native-имя. Полные квалифицированные
имена помогают только при отсутствии соответствующего пользовательского типа.

Parsed/ast.complete означает выполнение предусмотренных проходов без
зарегистрированной ошибки, а не поддержку всей семантики C#. Анализ не
проверяет сборочную корректность, достижимость или безопасность всего проекта.
Доступ к другим экземплярам/побочные эффекты не образуют полного heap-графа.

Бюджеты: до 120 000 узлов на каждый из двух проходов, 120 уровней обхода,
40 уровней выражения и 120 000 шагов поиска контекста; route хранит до 12 шагов происхождения плюс sink.
Исчерпание бюджета сохраняет partial. Сам модуль не читает файлы и не запускает
команды. csharp_bindings.py включён в отпечаток правил baseline, поэтому
изменившийся контекст возвращает известные находки на ревью.

## Регрессии и оценка

Два исходных FN из Cake — _file.Delete() и _directory.Delete(recursive) —
обнаруживаются по FileInfo/DirectoryInfo. Все четыре использованных файла Cake
перенесены в promoted; исходные тексты, метки и режимы сохранены. Исторические
24 входа v7 и первый JSON 1.7.0 не переписываются. На этапе 1.8.0 retained-v7 содержал
20 остальных случаев без Cake; после Go-ротации 1.9.0 осталось 16 без Cake/go-billy. Это ротация использованных данных, не новая
независимая оценка. Метки по-прежнему ожидают человеческого ревью.

## Выявленная граница v8

[Оценка v8](EVALUATION_V8_2026-11-18.md) на неизменном 1.9.0 выявила FN в
AbsolutePath.MoveCopy.cs проекта NUKE: target.DeleteFile/source.DeleteDirectory
вызывают extension methods соседнего AbsolutePath.Delete.cs, где уже есть
File.Delete/Directory.Delete. Определение закреплено для обоснования метки,
но каждый case подаётся отдельно, без helper-контекста.

Все четыре C#-файла v8 получили parsed без предупреждений; прямой System.IO
случай — TP, обёртка — FN, два остальных — TN. Required не гарантирует
обнаружение неподдержанной межфайловой связи. До её реализации критичные
пользовательские обёртки требуют ручного просмотра. Следующий этап —
ограниченные сводки выбранных extension methods/partial classes с отрицательными
случаями, проверяемыми типами и бюджетами. Первый результат v8 сохраняется.

API: [FileInfo.Delete](https://learn.microsoft.com/en-us/dotnet/api/system.io.fileinfo.delete),
[DirectoryInfo.Delete](https://learn.microsoft.com/en-us/dotnet/api/system.io.directoryinfo.delete).

## Связи между выбранными файлами

В проектном режиме сканер ищет один переход от вызова к определению
extension method или к методу соседней части partial class. Выбираются только
переданные в анализ файлы одной директории. Учитываются пространство имён,
видимые using и aliases, тип получателя, локальное затенение и объявленные
члены класса. Поддержан вызов без явных аргументов. Тело метода должно содержать
разрешённую операцию System.IO. Вложенные делегаты и локальные функции имеют
отдельную область. Вызов внутри callback в исходном файле означает возможный путь.

Для extension method без объявления типа в выбранных файлах допускается
совпадение аннотаций получателя внутри частей одного класса и пространства
имён. Такая связь получает certainty `possible`. При неоднозначных подходящих
методах выводится partial. Проектные лимиты составляют 128 файлов, 10 МБ
текста, 400 000 узлов, 8192 метода, 16 384 вызова-кандидата и 64 кандидата
на разрешение одного вызова. Исчерпание лимита отражается в диагностике.

Для воспроизводимой регрессии NUKE совместно передаются AbsolutePath.MoveCopy.cs
и AbsolutePath.Delete.cs из v8. В JSON и SARIF у вызовов в строках 164 и 224
появляется путь к строкам 22 и 34 второго файла. Первый результат однофайловой
оценки v8 сохранён. Изученная пара используется как регрессия.

Цепочки из нескольких обёрток, межкаталожные сборки, общий вывод перегрузок,
типов лямбд и generic, а также виртуальная диспетчеризация требуют дополнительного
анализа. Компилятор, MSBuild и код проверяемого проекта не запускаются.
