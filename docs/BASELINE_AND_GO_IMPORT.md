# Контекст baseline и импорт Go (v1.3.0)

[Указатель](README.md) · [Руководство пользователя](USER_GUIDE.md).

## Baseline schema 2

Отпечаток находки версии 1 сохраняется для совместимости с точечными исключениями.
Baseline schema 2 дополнительно содержит SHA-256 выбранных входных данных, кода
анализаторов, версий используемых парсеров, настроек, графа зависимостей и политики
с порогом gate. Исходный код в baseline не записывается. `--project-id` задаёт
устойчивую идентичность проекта, например путь проекта в GitLab; абсолютный путь
checkout и номер строки не входят в контекст.

Контекст учитывает **весь выбранный набор файлов**, кроме `.md`, `.mdx`, `.rst`.
Для успешно разобранного Python используется AST без координат: добавление
комментария или пустой строки контекст не меняет. Для остальных входов используется
текст, поэтому даже изменение форматирования может потребовать нового рассмотрения.
Markdown по-прежнему сканируется: новые находки в нём имеют новые отпечатки.

Если изменились входы, правила, настройки, политика или зависимости, прежняя
находка получает `baseline_state=updated`, `policy_review_required=true` и список
`baseline_context_changes`. Она снова участвует в gate при `--only-new`.
Это закрывает случай добавленного вызова опасной функции при неизменном evidence.
Проверка консервативна: изменение другого файла проекта тоже возвращает известные
находки на ревью. Полный межфайловый граф вызовов и доказательство эквивалентности
поведения здесь не строятся. Не выбранные профилем файлы остаются вне этой гарантии.

| Состояние | `--only-new` |
|---|---|
| Новый отпечаток | Участвует в gate |
| Известный отпечаток, контекст совпал | Сохраняется в отчёте, решение `baseline` |
| Известный отпечаток, контекст изменился | `updated`, требуется ревью, участвует в gate |
| Неполный источник или включённый строгий этап | Код 2 сохраняет приоритет |

Schema 1 читается для сравнения, но не допускается для фильтрации `--only-new`:
CLI возвращает 2 с предложением пересмотреть и сформировать schema 2. Миграция
не должна автоматически утверждать старые риски.

```bash
# Одинаковые проект, политика и параметры на обоих шагах.
python protestware_check.py --path ../application --project-id team/application \
  --format json --output ../review.json --write-baseline ../baseline-v2.json
# Рассмотреть отчёт и утвердить baseline в защищённой конфигурации CI.
python protestware_check.py --path ../application --project-id team/application \
  --baseline ../baseline-v2.json --only-new --format json --output ../current.json
```

Дата, расположение отчёта и baseline, переключатель `--only-new`, ревизия без
изменения значимых входов не вызывают повторного рассмотрения сами по себе.
Действующие явные исключения политики продолжают применяться; просроченные
исключения baseline не скрывает.

## Доверенный экспорт Go

Сканер и `scripts/prepare_go_build_info.py` принимают JSON как данные. Они не
вызывают Go, не устанавливают зависимости проекта и не запускают его код.
Вывод `go list` подготавливается **отдельным доверенным заданием сборки** для
конкретной ревизии, набора целей, GOOS/GOARCH, тегов, версии Go, CGO и режима модулей.
Определения заданий и полученные артефакты должны быть защищены от подмены кодом MR.
Проверка хешей сама по себе не удостоверяет честность производителя снимка.

Пример для уже подготовленного доверенного окружения Linux, обычного модуля и
производственных целей `./...`. Команды Go ниже относятся к заданию-производителю;
сканер их автоматически не выполняет. `GOOS`, `GOARCH`, CGO, теги и версия
toolchain должны соответствовать реальному профилю сборки вашей организации.

```bash
export GOFLAGS='' GOTOOLCHAIN=local GOENV=off CGO_ENABLED=0
export GOOS=linux GOARCH=amd64
export GOWORK=off  # Для workspace укажите его абсолютный go.work внутри source-root.
source_revision="$CI_COMMIT_SHA"
go_info_dir="$(mktemp -d)"  # Все JSON находятся вне дерева исходного кода.

go env -json GOOS GOARCH GOVERSION CGO_ENABLED GOFLAGS GOWORK > "$go_info_dir/environment.json"
go list -mod=readonly -m -json all > "$go_info_dir/modules.json"
go list -mod=readonly -deps -json ./... > "$go_info_dir/packages.json"

python /trusted/scanner/scripts/prepare_go_build_info.py \
  --source-root "$CI_PROJECT_DIR" --source-revision "$source_revision" \
  --modules "$go_info_dir/modules.json" --packages "$go_info_dir/packages.json" \
  --environment "$go_info_dir/environment.json" --output "$go_info_dir/build-info.json"

python /trusted/scanner/protestware_check.py \
  --path "$CI_PROJECT_DIR" --source-revision "$source_revision" \
  --project-id "$CI_PROJECT_PATH" --go-build-info "$go_info_dir/build-info.json" \
  --dependencies lock --dependency-strict --format json --output "$go_info_dir/report.json"
```

При workspace задайте явные цели входящих модулей, например `./app/... ./lib/...`,
и повторите `--target` при нормализации. Для `-tags=enterprise` передайте
`--tag enterprise`; для `-mod=mod` — `--mod-mode mod`. `GOFLAGS` должен быть пуст:
скрытые `-modfile`, `-overlay` и другие параметры не поддерживаются. Не собирайте
непроверенные проекты с привилегиями доверенного производителя: его изоляция и
контроль сетевого доступа относятся к существующей процедуре сборки организации.

## Что подтверждает импорт

### Параметры подготовки JSON

`python scripts/prepare_go_build_info.py --help` показывает справку helper.
Он читает только готовые данные доверенного производителя.

| Параметр | Значение |
|---|---|
| `--source-root DIR` | Корень исходников; обязателен, должен содержать основной модуль и локальные замены |
| `--source-revision SHA` | Обязательная ожидаемая ревизия: 40/64 строчных hex-символа |
| `--modules PATH` | Обязательный JSON/поток JSON-объектов из `go list -m -json all` |
| `--packages PATH` | Обязательный JSON/поток JSON-объектов из `go list -deps -json` для выбранных целей |
| `--environment PATH` | Обязательный JSON `go env` с GOOS, GOARCH, GOVERSION, CGO_ENABLED, GOFLAGS и GOWORK |
| `--tag TAG` | Один build tag; повторяется, по умолчанию список пуст |
| `--target TARGET` | Одна цель соответствующего `go list`; повторяется, по умолчанию `./...` |
| `--mod-mode readonly\|mod` | Использованный режим модулей; по умолчанию `readonly` |
| `--output PATH` | Обязательный путь нового нормализованного JSON |
| `--max-files N` | Лимит связываемых файлов; по умолчанию `10000` |
| `--max-bytes N` | Лимит байтов одного входного файла; по умолчанию `1000000` |
| `--max-total-bytes N` | Суммарный лимит связываемых байтов; по умолчанию `100000000` |

Raw JSON и нормализованный снимок должны находиться **вне source-root**; выход
не должен совпадать с входом. Числовые бюджеты положительны. Успех helper даёт
код 0, ошибка — 2. Успешная нормализация ещё не подтверждает честность производителя.

### Привязка и область полноты

Экспорт связывает основной модуль, локальные `replace`, `go.mod`, `go.sum`,
`go.work`/`go.work.sum`, Go/native исходники и файлы ресурсов с SHA-256.
Для `go:embed` консервативно учитываются каталоги до первой маски: появление нового
совпадающего файла также делает снимок устаревшим. Иногда включается весь каталог
пакета, что повышает число повторных экспортов. Чтение ограничено бюджетами;
symlink, выход за source-root, неполные JSON, пропущенные рёбра и циклы импортов
отклоняются. При импорте заново проверяются набор и хеши входов, ожидаемая ревизия;
наблюдённые при сканировании файлы дополнительно сверяются со снимком.

Ревизию передаёт доверенный CI: сканер не обращается к Git и не доказывает сам,
что каталог действительно является checkout указанного коммита. Дерево исходников
между экспортом и сканированием должно быть неизменяемым. JSON не является
подписанной аттестацией; байты модулей публичного module cache не проверяются.
`Sum`/`GoModSum` сохраняются как заявленные значения, без загрузки архивов.

В инвентарь попадают **используемые модули замыкания импортов заданных целей**,
а не все исторические версии `go.sum`. Выбранные, но не используемые модули видны
в `dependencies.go_builds[].unused_selected_modules`. Учитываются реальные
выбранные версии, удалённые/локальные замены, прямота, глубина и `via`.
Несколько снимков передаются повторением `--go-build-info`; профиль различает
одинаковые координаты в разных сборках. Дубли профилей делают анализ неполным.
Ревизия, профиль и хеш снимка сохраняются в JSON, advisory-находках и свойствах
компонентов CycloneDX. Эти сведения не заменяют подтверждение происхождения пакета.

Поддерживаются `readonly`/`mod` и обычные производственные пакеты. `-test`,
синтетические test-пакеты, `vendor`, overlay, альтернативный modfile и локальные
замены за пределами source-root отклоняются. Отдельные платформы и теги требуют
отдельных экспортов. `complete=true` относится только к заявленным профилям и
целям, а не ко всем возможным сборкам. Другие неразрешённые манифесты проекта
по-прежнему делают общую инвентаризацию неполной. Без импорта действует прежний
консервативный разбор `go.mod`/`go.sum`.

Описание исходных JSON: [go list](https://pkg.go.dev/cmd/go#hdr-List_packages_or_modules).
Реальный round-trip с собственным безвредным Go-модулем и локальной заменой
проверяется отдельным заданием CI; код из внешнего корпуса не собирается.
