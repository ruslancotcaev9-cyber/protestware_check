# Фабрики и возвращаемые функции JS/TS

Актуально для кода **1.6.0, unreleased**. [Проверка 1.6.0](VALIDATION_1_6_0.md) · [Локальные модули](JS_MODULE_ANALYSIS.md) ·
[Частичный анализ](JS_PARTIAL_ANALYSIS.md).

Граф выбранных текстов хранит сводки возвратов вместе со сводками удаляющих
эффектов. Возвращённая функция или объект получает отдельную захваченную среду
аргументов. Фабрики целевого проекта не исполняются, модули не загружаются.

```typescript
// wrappers.ts
export const make = fn => path => fn(path)
```

```typescript
// main.ts
import { make } from './wrappers.js'
import { rmSync } from 'node:fs'
const erase = make(rmSync) // создание обёртки; удаления здесь нет
const safe = make(() => {})
erase(path)               // возможный нативный вызов
safe(path)                // нативного удаления в этой цепочке нет
```

## Поддержка

| Форма | Область поддержки |
|---|---|
| Явный return / краткая arrow | Возврат известной функции, параметра или локального объекта |
| Замыкания | Отдельные захваченные аргументы экземпляров; новые параметры возвращённой функции |
| Композиция | make(wrap(fn)), make(fn)(path), простые значения по умолчанию, aliases |
| Возвращённый объект | Статически известные свойства/методы с захваченной средой |
| ESM/CommonJS | Фабрики через прежние локальные импорты и переэкспорты |
| Синхронная фабрика возвращает async-функцию | Её последующий вызов может содержать известную удаляющую операцию |

Создание обёртки и её вызов разделены. Если сама фабрика вызывает удаляющий API,
её вызов получает файловый сигнал. Удаление только внутри возвращённой функции
не превращает создание обёртки в удаление. В самом исходном файле тело функции
по-прежнему может содержать находку присутствия операции без доказательства
вызова извне. Полноценного CFG/анализа достижимости нет.

## Сводки, трассы и бюджеты

Рабочая очередь связывает аргументы, захваченную среду, эффекты и возвращаемые
значения. Новые результаты ставят зависимые контексты в очередь; корневые вызовы
перепроверяются после изменения возвратов. Сводки растут до стабилизации или
исчерпания бюджета. Рекурсивный возврат без базового значения не создаёт
доказанной вызываемой функции. Safe/native экземпляры не смешиваются.

JSON dataflow и SARIF codeFlows сохраняют factory, return, capture, импорты,
вызов и конечную операцию. Это статическая связь, не доказательство исполнения
или злонамеренности. ast.modules.closures показывает число захваченных сред.

| Ресурс | Предел |
|---|---:|
| Захваченные среды | 1 024 |
| Абстрактные возвращаемые значения на контекст | 32 |
| События сводок: вызовы, возвраты, повторные корневые проверки | 40 000 |
| Трасса в кеше/отчёте | 24 шага с сохранением конечной операции |

Также действуют прежние 2 048 контекстов, 20 000 символических значений,
200 000 шагов разрешения и лимиты выбранных файлов. Исчерпание бюджета остаётся
partial с наблюдениями; required возвращает 2. summary_steps теперь учитывает
также возвраты/корни; его значения между версиями имеют разный состав работы.

## Ограничения

Результат async-фабрики и генератора не принимается за синхронно возвращённую
функцию. Запрос известного вызываемого возврата даёт диагностику неподдержанной
формы. Создание генератора не приписывает вызывающему его тело; исполнение
итератора явно не поддержано. Await/Promise dispatch, yield/next, bind/call/apply,
классы-конструкторы, getter/proxy-эффекты, полная типизация и произвольные побочные
изменения захваченных переменных не моделируются.

Запись в свойство результата фабрики даёт partial. Последующие известные aliases
консервативно теряют идентичность; прежние вызовы сохраняют свои снимки.
Сложные heap-alias связи и изменения через другие функции охватываются неполно.
Сторонний пакет не становится нативным API по имени. Неизвестный возврат не
доказывает операцию; отсутствие находки не гарантирует безопасность.

Закреплённая регрессия rimraf проверяет retryBusy(fixEPERM(unlink)) и синхронную
форму: строки вызова 122/176 в src/rimraf-windows.ts обнаруживаются, создание
обёрток в строках 26–29 удалением не помечается. Источники, метки и режимы
корпусов сохранены; новой независимой внешней выборки на этом этапе нет.
