# Авторская оценка GEO_ACTION на шести фрагментах Python

На шести закреплённых фрагментах правило обнаруживает geo-4 и geo-6. Geo-2 остаётся единственным пропуском. Все три отрицательных примера проходят без срабатываний. Два прогона дали одинаковые исходы, строки и статусы разбора. [Результаты на исходных фрагментах](evaluation/geo-v1-telegram-2026-11-24/comparison.json).

## Geo-2 и контекст обработчика Telegram

В ветви `country == "ru"` функция `getLocation(update, context)` вызывает `context.bot.sendChatAction` и `context.bot.send_message`. Параметр `context` не имеет аннотации. В аргументах встречаются константы `telegram.ChatAction.TYPING` и `telegram.ParseMode.MARKDOWN`. Они описывают аргументы вызовов и не устанавливают, какому объекту передано сообщение. [Исходная ветвь RU](https://github.com/ravindraten/Covid19WorldStats/blob/22ead0e613c22a94c67dc1e3480a1c1c1154dc87/Bot.py#L931-L949).

| Вход сканера | Какие сведения доступны | Результат в исходных строках |
|---|---|---|
| Зафиксированный фрагмент, строки 752–1156 | Тело обработчика без импорта классов SDK, аннотации и регистрации | `GEO_ACTION` отсутствует. В авторской оценке это FN. Разбор фрагмента полный. |
| Полный `Bot.py`, строки 1–2302, та же ревизия | Импорт `Updater` и `MessageHandler` на строке 1, создание `Updater(..., use_context=True)` на 2259, получение диспетчера на 2262, регистрация `getLocation` на 2296 | В ветви RU обнаружены **934, 935, 936 и 949**. У двух новых находок на 935 и 936 отчёт показывает привязку к Telegram. Полный файл имеет статус `partial` из-за лимита вызовов анализа потоков данных Python. |

В JSON и SARIF у находок на 935 и 936 указаны `resolved_symbol` (`telegram.Bot.send_chat_action` или `telegram.Bot.send_message`), `binding_basis=telegram-handler-registration` и `binding_certainty=possible`. Трасса проходит через строки 2259, 2262 и 2296, затем через условие на 931 к месту вызова. Это возможная операция по исходному коду. Пример не запускался. Обе строки получают также `NET_DYNAMIC`. Обычные сетевые обращения на 1056 (IT) и 1133 (MY) сохраняют сетевую классификацию. [Регистрация обработчика](https://github.com/ravindraten/Covid19WorldStats/blob/22ead0e613c22a94c67dc1e3480a1c1c1154dc87/Bot.py#L2257-L2297) · [Проверенные трассы и диагностика](evaluation/geo-v1-telegram-2026-11-24/paths.json).

На 934 и 949 сканер по-прежнему находит вызовы `requests.get` через локальные функции. Пятая размеченная строка, 947, вызывает `countryTrend`. Эта функция получает `context` отдельным параметром и использует `context.bot.send_photo` на 1994 и 2075. Передача типа между функциями и метод `send_photo` выходят за текущий охват. [Код countryTrend](https://github.com/ravindraten/Covid19WorldStats/blob/22ead0e613c22a94c67dc1e3480a1c1c1154dc87/Bot.py#L1986-L2075).

**Границы модели.** Сканер поддерживает две операции синхронного API и их имена в camelCase. Происхождение параметра устанавливается по явной аннотации импортированным `telegram.ext.CallbackContext` либо по регистрации синхронной функции из того же модуля в `MessageHandler` через диспетчер `Updater` с явным `use_context=True`. В случае аннотации трасса указывает её строку и основание `telegram-context-annotation`. Совпадение имени метода, неподтверждённый диспетчер, подмена параметра или его поля и пользовательский класс исключены контрольными примерами. Версия зависимости в исследуемом проекте не закреплена. Контракт сверен с документацией python-telegram-bot 13.15. [Зависимости исходного проекта](https://github.com/ravindraten/Covid19WorldStats/blob/22ead0e613c22a94c67dc1e3480a1c1c1154dc87/requirements.txt) · [Updater](https://docs.python-telegram-bot.org/en/v13.15/telegram.ext.updater.html) · [MessageHandler](https://docs.python-telegram-bot.org/en/v13.15/telegram.ext.messagehandler.html) · [CallbackContext.bot](https://docs.python-telegram-bot.org/en/v13.15/telegram.ext.callbackcontext.html#telegram.ext.CallbackContext.bot) · [Методы Bot](https://docs.python-telegram-bot.org/en/v13.15/telegram.bot.html).

На шести исходных фрагментах получены **TP 2, TN 3, FP 0, FN 1**, ошибок и частичных разборов нет. Полный файл проверен отдельно и в этот подсчёт не входит. На 190 примерах остальных корпусов до и после изменения совпали исходы и статусы разбора. В пяти попарных прогонах на одном ядре медиана времени для шести фрагментов составила 42,99 мс до изменения и 42,56 мс после. [Значения пяти прогонов](evaluation/geo-v1-telegram-2026-11-24/timings.json) · [Контрольные примеры](../tests/test_python_telegram.py).

Модель использует однозначно связанные синхронные функции текущего модуля и явный импорт сетевой функции. Она проверяет форму аргументов и сохраняет один возможный путь от места вызова до сетевой операции, в том числе через одну промежуточную функцию. Значения параметров внутри такого пути не подставляются. Переопределения, методы неизвестных объектов, генераторы и декорированные функции остаются за пределами этой модели.

В пяти попарных запусках на одном логическом ядре медиана времени анализа всех шести фрагментов составила 42,94 мс до изменения и 42,78 мс после. Измерение охватывает сканирование и подсчёт по строкам. [Значения всех прогонов и версии кода](evaluation/geo-v1-branch-calls-2026-11-24/timings.json).

## Первое измерение

21 ноября 2026 года правило `GEO_ACTION` пропустило все три размеченных действия. На трёх отрицательных фрагментах срабатываний не было. Вручную отобраны шесть фрагментов из разных проектов. Результат описывает эту выборку и относится только к правилу Python. [Первый отчёт в JSON](evaluation/geo-v1-author-2026-11-21/geo-author-first.json).

Владелец проекта участвовал в отборе примеров или первоначальной разметке и принял шесть меток без поправок. В отчёте указан режим `author-regression`. В журнале независимого ревью у всех шести записей статус `pending`. Теперь эти примеры служат для регрессии. Для следующего первого слепого измерения потребуется новая выборка. [Комментарий о ревью](https://github.com/ruslancotcaev9-cyber/protestware_check/pull/17#issuecomment-7065471960) · [Авторское решение](../tests/corpus/geo-v1-author-decision.json) · [Журнал независимого ревью](../tests/corpus/geo-v1-review.json).

## Что засчитывается

Единица учёта — фрагмент. В положительном примере проверка страны RU/BY или локали ru/be влияет на достижимость записи в файл либо сетевого вызова. Для TP правило должно указать хотя бы одну заранее отмеченную строку действия или вызова обёртки. В отрицательном фрагменте любое срабатывание `GEO_ACTION` считается FP. Мотив автора проекта при разметке не оценивается. [Границы фрагментов, ревизии и эталонные строки](../tests/corpus/geo-v1.json) · [Исходный лист разметки](GEO_ACTION_REVIEW.md).

| Пропущено положительных фрагментов (FN) | 3 |
| Отрицательных фрагментов без срабатывания (TN) | 3 |
| Отрицательных фрагментов с ложным срабатыванием (FP) | 0 |

## Как повторить измерение

Из корня репозитория выполните команды в Python 3.11 или новее. `prepare` загружает отсутствующие исходники с GitHub по закреплённым Git blob SHA и проверяет каждый файл по Git blob SHA и SHA-256. Если все шесть файлов уже в каталоге, команды работают офлайн. Сканер разбирает исходники как текст.

```bash
python -I scripts/evaluate_geo.py prepare --sources ../geo-input
python -I scripts/evaluate_geo.py compare --sources ../geo-input --output ../geo-comparison-new.json
python -I tests/pinned_python_geo.py --sources ../geo-input --output ../geo-paths-new.json
```

Команда `compare` проверяет хеш первого отчёта и применяет прежние критерии к текущему сканеру. В `comparison.cases` для каждого фрагмента указаны его SHA-256, ожидаемые строки, исходы двух запусков, состояние разбора и фактические строки. Поля `comparison.reference` и `comparison.candidate` указывают версии. Для текущего сканера сохраняются SHA-256 файлов правил и подсчёта. В Git-копии записывается коммит и состояние проверяемых файлов. При запуске из архива поле коммита пустое.

Для воспроизведения первого результата используйте рабочую копию исторического коммита. Сохранённый выше каталог исходников подходит для обеих команд.

```bash
git worktree add --detach ../protestware-geo-reference 18f3b6cf84b88c9a6cc3a1a5200cb77a1038d29d
python -I ../protestware-geo-reference/scripts/evaluate_geo.py evaluate-author --sources ../geo-input --output ../geo-author-new.json
```

Для каждого запуска укажите новое имя отчёта. Перед подсчётом скрипт сверяет манифест выборки с авторским решением и проверяет хеши файлов детектора. Исторический манифест содержит 29 файлов, текущий содержит 31. Код возврата 0 означает, что измерение завершилось без ошибок. Пропуски и ложные срабатывания отражаются в `overall`. Команда `python -I scripts/evaluate_geo.py review` показывает состояние исходного журнала независимого ревью.

Первый и повторный запуски совпали по всем полям, кроме `performance.elapsed_seconds` и `performance.median_case_seconds`. SHA-256 каждого отчёта записан в файле сравнения. Версия Python, коммит сканера, хеши выборки, правил, скрипта и авторского решения сохранены вместе с отчётами.
