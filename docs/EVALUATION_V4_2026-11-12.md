| Характеристика | Значение |

Новые источники: Afero, GitHub CLI, ASP.NET Core, fs-extra, rimraf, SQLFluff,
Click и pip. На каждый язык добавлены четыре положительных и четыре отрицательных
примера. Отрицательная метка относится только к указанной операции/правилу:
например, создание файла может быть отрицательным для FS_DELETE.

Выборка целевая, не случайная: она проверяет формы API, в том числе файловые
обёртки за пределами нынешнего разрешения импортов. SQL-часть взята из
синтаксических фикстур SQLFluff; отдельный целый файл может содержать одну команду.
Это не проверка всех файлов 15 проектов. Общие библиотеки, похожие реализации
и вспомогательные модули делают наблюдения зависимыми.

Все 48 новых файлов заранее выбраны для стандартного режима **auto**.
Прежние 24 примера сохраняют **required**. Режим записан в каждом примере и
зафиксирован до первого измерения. Результаты когорт публикуются отдельно;
их нельзя интерпретировать как сравнение качества режимов на одинаковых входах.

**Все 72 метки предварительные:** подготовлены ассистентом по исходникам,
независимого человеческого подтверждения нет. Положительная метка означает
возможную файловую/SQL-операцию, а не malware, protestware или доказанную
достижимость. [Материалы ревью](CORPUS_LABEL_REVIEW_V4.md),
[порядок работы](CORPUS_REVIEW_GUIDE.md).

Очистка файлов в этих библиотеках легитимна; FN не означает вредоносности проекта.

## Восемь частичных анализов

64 примера разобраны без диагностированной неполноты, 8 — частично:

| ID | Зафиксированная диагностика | Результат по целевому правилу |
|---|---|---|
| afero-whole-v4-5 | Достигнут рекурсивный вызов taint | TN |
| aspnetcore-whole-v4-1 | Достигнут рекурсивный вызов taint | TP, языковой шаблон |
| aspnetcore-whole-v4-4 | Рекурсивный taint и syntax recovery | TP, языковой шаблон |
| fs-extra-whole-v4-2 | Достигнут рекурсивный вызов taint | TP, текстовая эвристика |
| fs-extra-whole-v4-3 | Рекурсия, глубина и бюджет вызовов | TP, текстовая эвристика |
| sqlfluff-whole-v4-6 | Syntax recovery | TN |
| sqlfluff-whole-v4-7 | Syntax recovery | TN |
| sqlfluff-whole-v4-8 | Syntax recovery | TN |

В auto доступные находки и fallback сохраняются. Эти восемь результатов не
подтверждают полного AST-охвата; в required диагностированная неполнота дала бы
код 2. Два TP fs-extra основаны на текстовом совпадении, а не на разрешённой
идентичности файлового API. Изменение полноты разбора может менять применение
fallback — это нужно учитывать при дальнейшем развитии резолвера.

`metrics_valid=true` означает отсутствие фатальных ошибок данного прогона;
`analysis.complete=false` отдельно показывает частичный анализ. Отсутствие
backend или ошибка, отмеченная как degraded, остаются ошибкой оценки и кодом 2.
Частичное восстановление синтаксиса явно сохранено в диагностике; его нельзя
называть безошибочным полным разбором.
