# Локальные модули JavaScript и TypeScript

Актуально для кода **1.5.0, unreleased**. [Руководство](USER_GUIDE.md) ·
[Технический справочник](TECHNICAL_REFERENCE.md) · [Пределы оценки](../tests/corpus/README.md).

При сканировании каталога или GitHub-репозитория `build_report` строит ограниченный
граф JS/TS из текстов, уже выбранных профилем, исключениями и лимитами чтения.
Он не открывает дополнительные модули, не импортирует проверяемый код и не запускает
Node.js, сборку или установку зависимостей. Для AST нужны заранее загруженные
грамматики `javascript`, `typescript`, `tsx`.

## Что разрешается

| Связь | Поддержка |
|---|---|
| Node API | `fs`, `node:fs`, `fs/promises`, `node:fs/promises`; удаляющие методы и Sync-формы |
| ESM | Named/default/namespace imports, статические локальные переэкспорты, `export *`, `export * as` |
| CommonJS | Литеральный `require`, прямые `exports.name` / `module.exports`, объекты и функции |
| TypeScript | Уникальная подстановка `.js` → `.ts/.tsx`; type-only связи не являются runtime API |
| Локальные функции | Прямые вызовы обёрток, передача функции параметром, явный вызов callback, простые значения по умолчанию |
| Пути | Относительные пути внутри выбранного проекта; extensionless/index lookup для TS и `require` |

Обнаруживается **возможная операция**, а не доказанная достижимость или вредоносность.
Тела функций рассматриваются и без доказательства вызова извне. При этом простое
объявление вложенной функции не делает вызывающую обёртку удаляющей: нужен вызов.
Некоторые литеральные мёртвые ветви и инструкции после прямого return/throw исключаются.
Полноценного CFG или проверки типов нет.

Пример из двух выбранных файлов:

```javascript
// src/files.js
import { rmSync } from 'node:fs'
export const erase = path => rmSync(path)
```

```javascript
// src/main.js
import { erase } from './files.js'
if (country === 'RU') erase(path)
```

В `main.js` возможны `FS_DELETE` и `AST_GEO_ACTION`. JSON `dataflow` и SARIF
`codeFlows` сохраняют пути/строки импорта, экспорта, обёртки и нативной операции.
Маркер `module_analysis=selected-text-only` обозначает этот проход;
`binding_certainty=possible` не задаёт вероятность злонамеренности.
Вызов Python API `scan_text` без project-контекста сохраняет однофайловый анализ.

## Неоднозначности и бюджеты

За пределами корня ничего не читается. Абсолютные, URL, обратные разделители,
кодированные пути, query/hash не используются для локального разрешения.
Если найдено несколько кандидатов, выбранный модуль отсутствует, обнаружен цикл,
spread/вычисляемое свойство объекта, неподдерживаемая мутация экспортов или исчерпан бюджет, выводится диагностика.
Статус передаётся импортёрам. В `auto` сохраняются наблюдения и прежние эвристики;
`ast.complete=false`. В `required` неполнота даёт код 2. При отсутствии грамматики
AST остаётся недоступным; `off` не строит граф.

| Ресурс одного графа | Предел |
|---|---:|
| JS/TS-модули / UTF-8 байты | 256 / 10 000 000 |
| Посещения узлов / глубина обхода | 500 000 / 250 |
| Рёбра локальных импортов | 2 048 |
| Глубина импортов/вызовов | 24 |
| Контексты вызовов / символические значения | 2 048 / 20 000 |
| Шаги разрешения значений | 200 000 |
| Трасса одной находки | 24 шага, с сохранением конечной операции |

Обычные общие `--max-files` / `--max-total-bytes` продолжают действовать до
построения графа. `ast.modules` сообщает количество модулей, байты, рёбра,
контексты и полноту. Исходные тексты буферизуются в пределах общего бюджета;
это увеличивает память по сравнению с прежним потоковым обходом.

## Оставшиеся ограничения

Не разрешаются сторонние пакеты по имени (`graceful-fs`, `fs-extra`), `tsconfig`
paths, package exports, произвольные загрузчики, динамические импорты, `import =`,
require ESM, `.mts/.cts`, возвращаемые функции/фабрики, Promise callback dispatch, отражение,
виртуальные вызовы и произвольные изменения через другие функции. Слияние ветвей,
мутации и циклы обрабатываются консервативно и могут терять возможные пути.
Полнота AST означает отсутствие зарегистрированной ошибки прохода в его области,
а не полное семантическое покрытие языка. Межфайловой анализ ограничен файловыми
операциями; сетевой taint по-прежнему ограничен одним файлом.

Для JavaScript/CJS поиск без расширения ограничен `.js`/`index.js`; `.cjs/.mjs`
требуют точного имени. Подстановка `.mjs/.cjs` в `.ts/.tsx` не выполняется.
Правила выбора путей намеренно ограничены. Основание для явных расширений:
[Node ESM](https://nodejs.org/api/esm.html#mandatory-file-extensions);
для подстановки расширений — [TypeScript](https://www.typescriptlang.org/docs/handbook/modules/reference.html#file-extension-substitution).
Это не полная реализация резолвера Node или TypeScript.
