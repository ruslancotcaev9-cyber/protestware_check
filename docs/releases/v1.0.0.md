# protestware-check v1.0.0 — historical release candidate

> These are historical candidate notes, not the current main documentation or
> confirmation that v1.0.0 was published. For the current code and status see
> [README](../../README.md) and [release checklist](../RELEASE_CHECKLIST.md).

A static, non-executing triage tool for potential protestware indicators and
software supply-chain risks. Scans source code and supported dependency
manifests, optionally correlating repositories with third-party watchlists.
**A political statement or watchlist match does not establish malice.**

## Included

- Local-directory and GitHub-commit scanning.
- Python AST and Tree-sitter-powered structural analysis across supported
  languages (see `docs/USER_GUIDE.md` for per-language limitations).
- Geo-dependent action heuristics, bounded URL taint and C/C++ reachability,
  filesystem and network checks, JS request-flood and obfuscation indicators.
- Dependency inventory from supported lockfiles and optional official
  package-registry metadata.
- JSON, SARIF 2.1.0 and CycloneDX 1.6 outputs for audit/CI pipelines.
- Security policy, Apache-2.0 license, user guide and contribution guidance.

## Requirements

Python 3.11+. No scanned code or scanned package dependencies are executed.
Optional analyzers require the packages in `requirements-ast.txt` and
`requirements-resolver.txt`; Tree-sitter grammars must be available.

## Trust model

This is not a full inter-file SAST engine or a malware sandbox. A clean result
is **not** a safety certification; all alerts require verification.
Dynamic URL and call-graph paths are bounded and often path-insensitive.
Private-source excerpts in reports must be handled confidentially.

For installation and examples see `README.md` and `docs/USER_GUIDE.md`.
For security contact see `SECURITY.md`.

## Integrity

The release draft includes a source archive and SHA256SUMS. Verify the
archive's SHA-256 before use; the checksum authenticates bytes only when
obtained from a trusted release channel.
