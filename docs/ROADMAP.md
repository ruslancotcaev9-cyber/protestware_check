# План развития

Состояние на 11.11.2026, после кода 1.3.0. Ниже перечислены **открытые задачи**;
сроки и наличие реализации не подразумеваются. Реализованные возможности описаны
в [истории изменений](../CHANGELOG.md), результаты — в
[отчёте оценки](EVALUATION_2026-11-11.md).

| Приоритет | Направление | Критерий готовности |
|---|---|---|
| P1 | Go: разрешение dot import и алиасов известных файловых API | Распознаётся реальный `os.Remove` через импорт; локальный одноимённый символ не становится удалением без основания; есть положительные и отрицательные проверки |
| P1 | SQL: `TRUNCATE` с необязательным `TABLE` и дополнительные формы PostgreSQL | Поддержанные команды обнаруживаются; такие же слова в строках, идентификаторах и комментариях не дают находку исполняемой команды |
| P1 | Расширение внешней оценки | Метки проверены специалистом; больше проектов и контекста целых файлов; примеры для настройки отделены от новых оценочных данных; FP/FN и ошибки публикуются раздельно |
| P2 | Детализация профилей Go и дополнительные режимы | Дополнительные параметры toolchain/архитектуры явно отражаются в профиле; тестовые и vendor-сценарии принимаются только после отдельных валидаторов и реальных CI-проверок |
| P2 | Межфайловые связи в анализе | Ограниченное разрешение импортов/вызовов с трассировкой и бюджетами; неоднозначности и исчерпание лимитов остаются видимыми; target-код не запускается |
| P2 | Проверяемые контракты JSON | Схемы отчётов, baseline и Go-снимка, правила совместимости и миграции; некорректные данные дают управляемую ошибку |
| P3 | Подтверждение происхождения артефактов | Проверка утверждённого источника и целостности пакета/аттестации отделена от совпадения публичных координат и сообщения advisory |
| P3 | Воспроизводимость в закрытом контуре | Задокументированы закреплённое окружение, набор грамматик, обновление доверенных снимков и единый запуск в GitLab; результаты сопоставимы для одинаковых входов |

## Следующая итерация правил

Во внешнем наборе зафиксированы два пропуска P1: Go dot import и PostgreSQL
`TRUNCATE` без `TABLE`. При исправлении используемые примеры следует перенести в
регрессию и добавить в оценочный набор новые, ранее не использованные фрагменты.
Это сохранит смысл оценки на данных, по которым детектор не настраивался.

Для каждого изменения правил требуются объяснимое evidence, проверка обычного
легитимного кода и учёт полноты. Нулевая ошибка на малом корпусе не является
сертификацией безопасности проекта или доказательством злонамеренности пакета.
