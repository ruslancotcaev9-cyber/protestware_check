# План развития

Состояние на 12.11.2026, после кода 1.5.0. Ниже перечислены **открытые задачи**;
сроки и наличие реализации не подразумеваются. Реализованные возможности — в
[истории изменений](../CHANGELOG.md), результаты — в [расширенной оценке](EVALUATION_V4_2026-11-12.md).

| Приоритет | Направление | Критерий готовности |
|---|---|---|
| P1 | Расширение внешней оценки | Метки проверены специалистом; больше проектов и целых файлов; настройка правил отделена от новой оценки; FP/FN и ошибки публикуются раздельно |
| P1 | JS/TS: оставшиеся связи и свежая оценка | Новые целые файлы из других проектов после заморозки правил; отдельные проверки фабрик/возвращаемых функций и сторонних пакетов; отсутствие угадывания native API по имени |
| P2 | Частичный AST на реальном коде | Разобраны 8 случаев v4: рекурсивные связи/бюджеты Go/C#/JS и восстановление синтаксиса C#/SQL; диагностика и fallback остаются видимыми |
| P2 | Детализация профилей Go | Параметры toolchain/архитектуры отражены в профиле; тестовые и vendor-сценарии принимаются после отдельных валидаторов и реальных CI-проверок |
| P2 | Межфайловые связи в остальных языках | Ограниченное разрешение импортов/вызовов, объяснимые цепочки и учёт исчерпания лимитов |
| P2 | Воспроизводимость в закрытом контуре | Закреплённое окружение, набор грамматик, обновление доверенных снимков и единый запуск в GitLab; сопоставимые результаты для одинаковых входов |
| P3 | Происхождение артефактов | Проверка утверждённого источника и целостности пакета/аттестации отделена от публичных координат и advisory |

## Выполнено в последней итерации

В 1.5.0 добавлен ограниченный граф локальных JS/TS-модулей, статические
переэкспорты, прямые обёртки и явно вызываемые callback-параметры. Есть бюджеты,
межфайловые трассы, диагностика циклов и partial/required. Восемь использованных
файлов rimraf перенесены в регрессию с закреплёнными локальными модулями;
четыре положительных обнаруживаются, три сохраняют partial. Внешний набор
сокращён до 64 сохранённых примеров; свежая выборка в этом этапе не добавлялась.
[Поддержка и пределы](JS_MODULE_ANALYSIS.md).

## Предыдущие итерации

V4 расширена с 24 до 72 примеров: добавлены 48 целых файлов из восьми новых
проектов; код детектора 1.4.0 заморожен. Полный CI — 421 тест. Выявлены 6 FN и
8 partial, опубликован исходный JSON измерения. Все 72 метки остаются предложениями:
подготовлены журнал и таблица для независимого ревью. Поэтому задача P1 по
экспертному подтверждению меток остаётся открытой. [Результаты](EVALUATION_V4_2026-11-12.md).

В 1.4.0 выполнена прежняя задача P1 для JSON: пять схем отчёта/baseline/Go/status,
независимая версия отчёта, офлайн-helper, строгое чтение, проверка согласованности
gate и 27 тестов контрактов с сохранёнными данными 1.3.2. Полный CI: 403 теста без
пропусков; старые корпуса проходят без FP/FN и ошибок. Правила детекторов и сами
оценочные примеры на этом этапе не менялись. [Подробности](JSON_CONTRACTS.md).

В 1.3.2 выполнена прежняя задача P1 для `fs.promises.rm`: добавлены импортная
идентичность, псевдонимы, деструктуризация и затенение JS/TS. Использованные
8 внешних JS/TS-примеров перенесены в регрессию; вместо них добавлены примеры
других исходных файлов. Общая внешняя оценка: 24 примера, 16 групп исходников,
10 целых файлов, 7 проектов. Остальные 16 примеров сохранены из предыдущей оценки.

Независимая проверка меток специалистом остаётся открытой задачей. Также не
разрешаются произвольные динамические загрузчики JS/TS, фабрики JS/TS, межфайловые объявления остальных языков
и Go-алиасы значений функций. Для изменений правил нужны объяснимое evidence,
отрицательные примеры обычного кода и учёт полноты. Нулевая ошибка малого корпуса
не является сертификацией безопасности или доказательством злонамеренности пакета.
