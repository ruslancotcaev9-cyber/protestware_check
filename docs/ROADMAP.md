## Выполнено в последней итерации

Для Python GEO_ACTION добавлено сравнение версий по исходным строкам на шести
закреплённых фрагментах. В geo-4 условие с `continue` связано с записью на 321
и копированием на 327. Теперь обнаружен один из трёх положительных примеров,
все три отрицательных проходят без срабатываний. CI повторяет авторскую проверку
на прежнем и текущем детекторах. [Сравнение и воспроизведение](GEO_ACTION_EVALUATION.md).

Сканер читает UTF-16 LE/BE с BOM. Параметр политики `min_analyzed_files`
задаёт минимальное число проанализированных файлов. Два вызова удаления NUKE
прослеживаются при совместном выборе вызывающего файла и определений C#.
Образ с закреплёнными грамматиками проверен на GitLab Runner, для включения
в существующий проект добавлен шаблон пилота. [Покрытие](POLICY_AND_CI.md) ·
[Регрессия NUKE](CSHARP_BINDING_ANALYSIS.md) · [GitLab в закрытом контуре](OFFLINE_GITLAB.md).

## Предыдущие измерения

Оценка v8 проверила неизменный код 1.9.0 на 24 новых целых файлах шести проектов:
TP11/TN12/FP0/FN1, все parsed без предупреждений. Пропуск — выбранная отдельно
C#-обёртка с extension methods в соседнем файле. 581 тест без пропусков;
прежние 48/46/56/16 входы и исходы неизменны. Метки pending, человеческого ревью нет.
[Первый JSON и пределы](EVALUATION_V8_2026-11-18.md).


В 1.9.0 добавлена ограниченная модель Go os.Root и конкретных обёрток между
выбранными package-файлами. Изученные Go-примеры перенесены в регрессию;
осталось 16 v7 cases. Поддержка interfaces, generic substitution, promoted
embedded methods и вычисление build-конфигураций остаются открытыми.
[Go-пределы](GO_ROOT_ANALYSIS.md) · [Проверка 1.9.0: 573 теста](VALIDATION_1_9_0.md).

В 1.8.0 добавлена ограниченная привязка C# FileInfo/DirectoryInfo по полям,
параметрам и конструкторам, с отрицательными проверками пользовательских типов
и затенения. Два Cake FN обнаруживаются в регрессии. Четыре использованных
Cake-файла перенесены; исходный v7 сохранён, на этапе 1.8.0 retained-v7 содержал 20
случаев. На этапе 1.8.0 Go os.Root/BoundOS оставались следующим приоритетом; см. этап 1.9.0 выше.
[C# пределы](CSHARP_BINDING_ANALYSIS.md) · [Проверка: 541 тест](VALIDATION_1_8_0.md).


Новая оценка v7 проверила замороженный код 1.7.0 на 24 целых файлах шести
ранее не использованных проектов. TP8/TN12/FP0/FN4, два partial; 516 тестов
без пропусков. Четыре FN Go/C# имеют parsed без предупреждений: нужны связи
типов/полей и экземпляров. Протокол и метки закреплены до результатов;
по исходам правила не менялись. Метки pending.
[Результаты и первый JSON](EVALUATION_V7_2026-11-17.md).


В 1.7.0 связываются уже выбранные исходники JS-пакетов. Шесть экспортов удаления
точного graceful-fs 4.2.11 моделируются по хешам пяти файлов, с происхождением в
JSON/SARIF. Два прежних пропуска fs-extra обнаруживаются на проектных входах;
ограничения внутренних модулей остаются видимыми. Восемь использованных файлов
перенесены в регрессию: наборы 48/38/56. Это не свежая независимая оценка.
[Поддержка](JS_PACKAGE_ANALYSIS.md), [проверка: 510 тестов](VALIDATION_1_7_0.md).

Новые целые файлы добавлены отдельной оценкой v7; независимое ревью меток/модели
остаётся открытым. Этапы 1.8.0–1.9.0 разобрали конкретные FN C#/Go,
сохраняя начальные результаты и отделяя регрессию от новых оценочных данных. Условные exports, другие версии адаптеров,
динамические загрузчики и полный API fs-extra остаются открытыми.

## Предыдущие итерации

В 1.6.0 добавлены ограниченные сводки возвращаемых значений и захваченные среды
фабрик JS/TS. Создание обёртки отделено от вызова, сохранены бюджеты и трассы;
async/generator-возвраты и мутации результата явно ограничены. Корпусные входы
и метки сохранены; свежая независимая выборка остаётся следующим направлением.
[Подробности](JS_FACTORY_ANALYSIS.md), [проверка: 485 тестов](VALIDATION_1_6_0.md).


В 1.5.1 сводки рекурсивных JS/TS-вызовов вычисляются рабочей очередью до
стабилизации; spread разрешается по читаемым свойствам и порядку записей.
Поиск NETWORK_FLOOD обходит конечный граф именованных функций без рекурсивного
обрыва и имеет общий бюджет на файл. На тех же проектных регрессиях rimraf
число partial снижено с пяти до двух; TP/TN сохранены. Два случая чтения
перекрываемых свойств остаются partial с исходными файлами и строками.
[Поддержка и пределы](JS_PARTIAL_ANALYSIS.md), [проверка: 464 теста](VALIDATION_1_5_1.md). Фабрики, сторонние API и
свежая независимая оценка остаются следующими этапами.

В 1.5.0 добавлен ограниченный граф локальных JS/TS-модулей, статические
переэкспорты, прямые обёртки и явно вызываемые callback-параметры. Есть бюджеты,
межфайловые трассы, диагностика циклов и partial/required. Восемь использованных
файлов rimraf перенесены в регрессию с закреплёнными локальными модулями;
четыре положительных обнаруживаются; все четыре остаются partial. Внешний набор
сокращён до 64 сохранённых примеров; свежая выборка в этом этапе не добавлялась.
[Поддержка и пределы](JS_MODULE_ANALYSIS.md).

Проверка: 447 unit-тестов без пропусков; регрессии 48/30 без FP/FN,
5 partial в перенесённых регрессиях. [Результаты и пределы](VALIDATION_1_5_0.md).

V4 расширена с 24 до 72 примеров: добавлены 48 целых файлов из восьми новых
проектов; код детектора 1.4.0 заморожен. Полный CI — 421 тест. Выявлены 6 FN и
8 partial, опубликован исходный JSON измерения. Все 72 метки остаются предложениями:
подготовлены журнал и таблица для независимого ревью. Поэтому задача P1 по
экспертному подтверждению меток остаётся открытой. [Результаты](EVALUATION_V4_2026-11-12.md).

В 1.4.0 выполнена прежняя задача P1 для JSON: пять схем отчёта/baseline/Go/status,
независимая версия отчёта, офлайн-helper, строгое чтение, проверка согласованности
gate и 27 тестов контрактов с сохранёнными данными 1.3.2. Полный CI: 403 теста без
пропусков; старые корпуса проходят без FP/FN и ошибок. Правила детекторов и сами
оценочные примеры на этом этапе не менялись. [Подробности](JSON_CONTRACTS.md).

В 1.3.2 выполнена прежняя задача P1 для `fs.promises.rm`: добавлены импортная
идентичность, псевдонимы, деструктуризация и затенение JS/TS. Использованные
8 внешних JS/TS-примеров перенесены в регрессию; вместо них добавлены примеры
других исходных файлов. Общая внешняя оценка: 24 примера, 16 групп исходников,
10 целых файлов, 7 проектов. Остальные 16 примеров сохранены из предыдущей оценки.

Независимая проверка меток специалистом остаётся открытой задачей. Также не
разрешаются произвольные динамические загрузчики JS/TS, async/generator-фабрики, межфайловые объявления остальных языков
и Go-алиасы значений функций. Для изменений правил нужны объяснимое evidence,
отрицательные примеры обычного кода и учёт полноты. Нулевая ошибка малого корпуса
не является сертификацией безопасности или доказательством злонамеренности пакета.
