# Статический анализ Go os.Root — 1.9.0

Сканер разрешает потенциальное удаление через `os.Root.Remove` и
`os.Root.RemoveAll`, а также через ограниченные обёртки выбранных файлов.
Проверяемые исходники служат данными: команды Go, сборка, загрузка модулей
и установочные скрипты для этого анализа не вызываются.

## Область разрешения

Для native identity нужен наблюдаемый импорт стандартного `os`.
Учитываются import aliases и затенение, объявленные типы полей/параметров,
`os.OpenRoot`, `Root.OpenRoot`, конструкторы и утверждения типов.
Top-level type alias сохраняет identity; новый определённый тип на основе
`os.Root` не получает его методы по одному лишь базовому типу.

Граф включает только переданные сканеру файлы с одинаковыми физическим
каталогом, package name, признаком `_test.go` и набором строк build-тегов.
Разные каталоги, тестовые группы и разные теги изолированы. Это осторожное
сопоставление текста тегов, а не вычисление допустимых конфигураций сборки.
Импортируемые Go-пакеты и дополнительные файлы автоматически не читаются.

Для конкретных локальных типов индексируются поля и аннотированные возвраты
функций/методов. Ограниченные сводки вызовов позволяют проследить
BoundOS → RootOS → os.Root при наличии обоих выбранных файлов.
Создание callback само по себе не переносит действие из его тела в фабрику.
Потенциальные удаления в самом callback могут учитываться отдельно.

## Результаты и полнота

`GO_FS_DELETE` и связанный `AST_GEO_ACTION` сохраняют `resolved_symbol`,
`binding_certainty=possible`, `binding_basis` и маршрут `dataflow`.
У Root/обёрток basis — `selected-go-types`; у прежних прямых функций —
`import-identity`. Это статическая связь API, а не доказательство исполнения,
достижимости пути или вредоносности проекта.

JSON `ast.go_modules` содержит счётчики файлов, байтов, пакетов, посещений,
разрешения типов, рёбер вызовов и сводок, а также `complete` и предупреждения.
SARIF сохраняет их в invocation properties `goModuleAnalysis`.
Диагностированная неполнота видна в `ast.complete=false`; required возвращает 2.
Успешный проход и `parsed` не означают полной семантики Go.

## Бюджеты и ограничения

По умолчанию: 128 файлов, 10 MB UTF-8 текста, 500 000 учитываемых посещений,
120 000 шагов разрешения, 4 096 объявлений, 8 192 ребра и 20 000 шагов сводок.
Глубина обхода — 120, выражений — 40, aliases — 24; маршрут ограничен 24 шагами.
Достижение лимита сохраняет наблюдённые находки и отмечает partial.
Сами парсеры работают до подсчёта AST-узлов: эти бюджеты не являются абсолютной
гарантией времени или всей нативной памяти.

Нет полного CFG/SSA, интерфейсного dispatch, generic substitution, разрешения
вызовов через значения функций, promoted embedded methods и компиляторных
областей локальных типов. Типы результатов range/receive не выводятся из
контейнера. Неизвестные внешние типы могут дать явную диагностику; некоторые
неподдержанные семантические пути могут остаться без неё. Имя Remove само
по себе не подтверждает native API. Отсутствие находок не гарантирует безопасность.

Изменение правил меняет контекст baseline schema 2: прежние находки требуют
повторного ревью. Номер отчёта остаётся schema 1.
