# Регрессионный и внешний оценочный наборы

| Файл | Назначение | Примеры | Режим CI |
|---|---|---:|---|
| `cases.json` | Собственные инертные регрессии | 48 | FP/FN и ошибки блокируют |
| `promoted.json` | Ранее оценённые и использованные для исправлений внешние примеры | 14 | FP/FN и ошибки блокируют |
| `external.json` | Внешняя оценка v2.1 | 24 | FP/FN публикуются; ошибки блокируют |

Новый оценочный набор содержит по 2 положительных и 2 отрицательных примера для
Go, C#, JavaScript, TypeScript, SQL и Python. Он включает 8 целых файлов,
14 исходных файлов и 7 открытых проектов. Фрагменты одного файла коррелируют;
поле `provenance.group` не позволяет считать их независимыми наблюдениями.
Это малый оценочный набор, не независимая экспертиза и не оценка качества на всех проектах.

Для каждого фрагмента зафиксированы репозиторий, commit SHA, путь, диапазон строк,
Git blob SHA, текст и SHA-256 фрагмента, лицензия и её SHA-256. В `licenses/`
сохранены лицензии источников; Node.js содержит собственный MIT-раздел LICENSE,
относящийся к выбранному файлу. Код дедентируется, CRLF заменяется на LF и при
необходимости добавляется явно указанный синтаксический wrapper. Исходные операции
не переписываются. Фрагменты никогда не импортируются и не исполняются.

Положительная метка означает наличие операции, указанной правилом, **не наличие
malware или protestware**: например, очистка временных файлов легитимна, но содержит
удаление. Метки и пояснения назначены при подготовке проекта, без независимого
человеческого арбитража. Правила детектирования не подгоняются под этот набор;
исходная версия детекторов отмечена `detector_reference_commit`. Метаданные набора,
число групп исходных файлов и целых файлов сохраняются в отчёте.

```bash
python scripts/evaluate_corpus.py --measure --output ../regression-metrics.json
python scripts/evaluate_corpus.py --corpus tests/corpus/promoted.json \
  --measure --output ../promoted-metrics.json
python scripts/evaluate_corpus.py --corpus tests/corpus/external.json \
  --report-only --measure --output ../external-metrics.json
```

Внешние FP/FN сохраняются и показываются отдельно; `--report-only` не превращает
их в успешные обнаружения. Ошибки парсера всё равно дают код 2 и блокируют задание.
CI сохраняет три JSON с хешем корпуса, метриками по языку/правилу и результатом
каждого примера. Время включает разбор примеров; загрузка грамматик не измеряется.
Результаты малой выборки не следует переносить на произвольные кодовые базы.

[Исторический прогон 1.3.0](../../docs/EVALUATION_2026-11-11.md) выявил Go dot import
и TRUNCATE без TABLE. Все 12 примеров этого набора стали регрессией. При первом
прогоне v2 обнаружился отказ общей SQL-грамматики на RESTART IDENTITY; два примера
из использованного SGML-файла также перенесены в регрессию и заменены в оценке
примерами другого исходного файла. Проверка запрещает пересечение исходных файлов
между `promoted.json` и `external.json`.

[Прогон 1.3.1](../../docs/EVALUATION_1_3_1.md): внешние TP=11, TN=12, FP=0, FN=1,
ошибок разбора нет. Остался пропуск `fs.promises.rm` из VS Code; он сохранён в
метриках. Два регрессионных набора проходят без FP/FN.

Дальнейшее развитие набора: новые проекты и контекст целых файлов, экспертное
подтверждение меток, отдельная обучающая выборка для будущих изменений правил.
После использования примера для настройки детектора он должен перейти в регрессию,
а оценочный набор — получить новые, ранее не использовавшиеся примеры.
