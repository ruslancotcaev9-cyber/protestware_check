# Регрессии и внешняя оценка

| Файл | Назначение | Примеры | Режим CI |
|---|---|---:|---|
| `cases.json` | Собственные инертные регрессии | 48 | FP/FN и ошибки блокируют |
| `promoted.json` | Использованные для исправлений внешние примеры | 22 | FP/FN и ошибки блокируют |
| `external.json` | Внешняя оценка v4 по предварительным меткам | 72 | FP/FN публикуются; ошибки оценки блокируют |

V4 сохраняет 24 примера v3 и добавляет **48 целых файлов** из восьми новых
проектов. Всего: 58 целых файлов, 64 группы исходников, 15 проектов; по 12 примеров
для Go, C#, JavaScript, TypeScript, SQL и Python. На каждый язык добавлены четыре
положительных и четыре отрицательных предложения меток. Выборка целевая, не
случайная; все файлы 15 проектов не сканировались. SQL-часть — фикстуры SQLFluff,
отдельный целый файл может содержать одну команду. Общие библиотеки коррелируют.

## Метки и происхождение

При формировании v4 все 72 метки подготовлены ассистентом и ожидают независимого
человеческого ревью. Положительная метка означает операцию указанного правила,
**не malware/protestware и не доказанную достижимость**. Отрицательная относится
только к этому правилу, не к безопасности файла. Прямые вызовы, локальные и
сторонние обёртки разделены в `by_operation_scope`.

Закреплены repository, commit SHA, путь/строки, Git blob SHA, исходный текст,
SHA-256 фрагмента, лицензия и её SHA-256. Целые файлы дополнительно сверяются
с Git blob SHA. Применяются CRLF-to-LF и dedent; wrappers старых фрагментов
объявлены явно. Новые целые файлы не получают wrappers или подмены импортов.
Код target-проектов не импортируется и не исполняется.

`supporting-sources.json` сохраняет контекст обёрток для ревью, а не для подстановки
в текст однофайлового анализа. `detector-freeze.json` фиксирует код/зависимости
от 1.4.0, тест сверяет SHA-256. Данные, метки и режимы зафиксированы до измерения.

## AST и интерпретация

Старые 24 случая сохраняют `required`; новые 48 целых файлов используют стандартный
`auto`. Режим записан в каждом случае; когорты показаны отдельно. В auto partial
сохраняет доступные находки/fallback и диагностику; required вернул бы ошибку.
Недоступный backend/degraded остаётся ошибкой даже в auto/report-only.

Отчёт включает `by_cohort`, `by_repository`, `by_ast_mode`, `by_ast_status`,
`analysis.complete`, `partial_cases`, сообщения и `matching_analyses`.
`metrics_valid=true` означает отсутствие фатальных ошибок оценки, а не полный
AST или проверенные человеком метки. Syntax recovery в auto отражается как
partial. Когорты с разными режимами не сравнивают режимы на одинаковых входах.

```bash
python scripts/evaluate_corpus.py --measure --output ../regression-metrics.json
python scripts/evaluate_corpus.py --corpus tests/corpus/promoted.json \
  --measure --output ../promoted-metrics.json
python scripts/evaluate_corpus.py --corpus tests/corpus/external.json \
  --review-file tests/corpus/external-review.json \
  --report-only --measure --output ../external-v4-metrics.json
```

Report-only не превращает FP/FN в обнаружения; ошибки оценки возвращают 2.
CI сохраняет три отчёта, журнал ревью и freeze-файл. SHA-256 и метрики относятся
к одному прочитанному снимку корпуса. Tracemalloc не включает всю нативную
память; загрузка грамматик не входит в измеренное время.

## Независимое ревью

`external-review.json` связывает решения с SHA-256 корпуса и каждого примера.
Prepare создаёт pending-записи и не перезаписывает существующие файлы. Заполненные
confirmed/disputed требуют имени, типа проверяющего, времени с часовым поясом и
обоснования; файл не удостоверяет личность/независимость. Спорные метки не
исправляются автоматически.

## Результаты и ротация

[Оценка v4](../../docs/EVALUATION_V4_2026-11-12.md): 421 unit-тест без пропусков;
регрессии 48/22 без FP/FN. Внешний набор: TP=30, TN=36, FP=0, FN=6; фатальных
ошибок оценки нет, **8 partial-анализов**. Все шесть FN относятся к JS/TS-обёрткам.
Предварительные метки и целевой подбор не позволяют переносить эти показатели
на произвольные проекты.

История: [1.3.0](../../docs/EVALUATION_2026-11-11.md) выявила Go dot import и
TRUNCATE без TABLE; [1.3.1](../../docs/EVALUATION_1_3_1.md) сохранила пропуск
fs.promises.rm; [1.3.2](../../docs/EVALUATION_1_3_2.md) обновила JS/TS-данные;
[контрактная проверка 1.4.0](../../docs/VALIDATION_1_4_0.md) повторила v3.

После настройки правил использованные примеры и связанный контекст переходят
в регрессию, оценка получает новые источники. Пересечение исходных файлов
promoted/external запрещено тестом. JSON первого прогона сохраняет исторические
FN и partial-диагностику.
