# Регрессионный и внешний оценочный наборы

| Файл | Назначение | Примеры | Режим CI |
|---|---|---:|---|
| `cases.json` | Собственные инертные регрессии | 48 | FP/FN и ошибки блокируют |
| `promoted.json` | Использованные для исправлений внешние примеры | 22 | FP/FN и ошибки блокируют |
| `external.json` | Внешняя оценка v3 | 24 | FP/FN публикуются; ошибки блокируют |

В оценке по 2 положительных и 2 отрицательных примера для Go, C#, JavaScript,
TypeScript, SQL и Python. Она включает 10 целых файлов, 16 исходных файлов и
7 открытых проектов. В 1.3.2 заменены все 8 использованных JS/TS-примеров,
16 примеров других языков сохранены. Это не полностью новая независимая выборка.
Фрагменты одного файла коррелируют; `provenance.group` сохраняет их общность.

Для каждого фрагмента закреплены репозиторий, commit SHA, путь, диапазон строк,
Git blob SHA, текст и SHA-256, лицензия и её SHA-256. В `licenses/` сохранены
лицензии источников. Код дедентируется, CRLF заменяется на LF; при необходимости
добавлен явно указанный синтаксический wrapper. Исходные операции не переписываются.
Нужные импорты/объявления берутся из того же upstream-файла: `binding_context`
содержит исходный текст, строки и SHA-256. Type-only `declare const fs` не
подменяет реальный импорт. Собственные JS/TS-регрессии явно подключают Node fs;
это инертные фикстуры для анализа. Фрагменты никогда не импортируются и не исполняются.

Положительная метка означает наличие операции, указанной правилом, **не наличие
malware или protestware**. Например, легитимная очистка временных файлов содержит
удаление. Метки назначены при подготовке проекта без независимого человеческого
арбитража. `detector_reference_commit` фиксирует проверенную версию детектора,
а хеш корпуса — точные входные данные. Данные для настройки правил переходят
в регрессию; после ротации новые JS/TS-фрагменты не использовались для настройки.
Метаданные, число групп и целых файлов сохраняются в отчёте.

```bash
python scripts/evaluate_corpus.py --measure --output ../regression-metrics.json
python scripts/evaluate_corpus.py --corpus tests/corpus/promoted.json \
  --measure --output ../promoted-metrics.json
python scripts/evaluate_corpus.py --corpus tests/corpus/external.json \
  --report-only --measure --output ../external-metrics.json
```

`--report-only` не превращает FP/FN в успешные обнаружения. Ошибки парсера дают
код 2 и блокируют задание. CI сохраняет три JSON с хешем корпуса, метриками по
языку/правилу и результатом каждого примера. Время включает разбор, но не
загрузку грамматик. Память `tracemalloc` не включает всю память нативных парсеров.

[Прогон 1.3.0](../../docs/EVALUATION_2026-11-11.md) выявил Go dot import и TRUNCATE
без TABLE. Все 12 примеров стали регрессией; затем добавлены 2 использованных
SQL-примера. [Прогон 1.3.1](../../docs/EVALUATION_1_3_1.md) сохранил FN для
`fs.promises.rm`. В 1.3.2 все 8 JS/TS-примеров v2.1 стали регрессией и заменены
данными других исходных файлов. Тест запрещает пересечение исходных файлов
между `promoted.json` и `external.json`.

[Прогон 1.3.2](../../docs/EVALUATION_1_3_2.md): 376 unit-тестов без пропусков,
все три набора без FP/FN и ошибок. Результаты малой выборки нельзя переносить
на произвольные кодовые базы. Следующие задачи: новые проекты и целые файлы,
экспертное подтверждение меток, отдельные данные для настройки будущих правил.
