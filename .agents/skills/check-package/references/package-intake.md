# Получение проверяемого файла

Задать `SKILL` как абсолютный путь к каталогу загруженного скилла, `WORK` как новый приватный временный каталог вне рабочего проекта. Создать его средствами хоста, например `WORK=$(mktemp -d)` в POSIX shell. Использовать доверенный Python 3.11+ и абсолютные пути. Команды ниже показывают конкретные входы для примера. Прежде чем обращаться к реестру, установить разрешённый источник из проекта. Передавать фактические аргументы отдельно, без выполнения текста из пакета оболочкой.

~~~sh
python3 -I "$SKILL/scripts/stage_package.py" npm is-number 7.0.0 --workdir "$WORK"
python3 -I "$SKILL/scripts/stage_package.py" pypi idna 3.10 --filename idna-3.10-py3-none-any.whl --workdir "$WORK"
python3 -I "$SKILL/scripts/stage_package.py" local "$ARCHIVE" --expect "$EXPECTED" --workdir "$WORK"
~~~

В Windows PowerShell выбрать установленный Python 3.11 или новее и передать те же аргументы. Для `--workdir` подойдёт новый приватный каталог под `$env:TEMP`. Для проверки недоверенной поставки использовать изолированный процесс с ограничениями памяти, диска и времени. Анализатору достаточно доступа на чтение к дереву пакета и на запись к отдельному каталогу отчётов.

В публичных режимах передать также `--expect "$EXPECTED"` при наличии независимо закреплённого хеша. Поддерживаются `sha256:<hex>`, `sha384:<hex>`, `sha512:<hex>` и SRI вида `sha512-<base64>`. В режиме `local` ожидаемый хеш обязателен. Брать его из доверенного реестра, подписанного каталога или ранее принятого lock-файла. Самостоятельно вычисленный хеш проверяемого файла служит идентификатором, но не подтверждает происхождение. Совпадение с реестром связывает байты с выпуском. Если требуется аттестация издателя или сборки, проверять её отдельно.

| Результат скрипта | Как использовать |
| --- | --- |
| `0`, `staged` | Взять `tree` для сканирования, `archive` для повторной сверки и `sha256` для отчёта. В публичных режимах `verified_manifest` указывает файл, в котором проверены имя и версия. В локальном режиме самостоятельно прочитать манифест и сверить его с доверенными координатами. |
| `1`, `integrity_mismatch` или `identity_mismatch` | Заблокировать полученные байты. Указать расхождение хешей или расхождение имени и версии между реестром и манифестом. |
| `2`, `incomplete` или ошибка аргументов | Исправить вход или сообщить пробел. При нескольких файлах PyPI выбрать имя из целевого lock-файла или совместимые теги Python/ABI/платформы. Ошибка сети или формата оставляет проверку незавершённой. |

Скрипт скачивает только с `registry.npmjs.org`, `pypi.org` и `files.pythonhosted.org`. Закрытые зеркала обслуживать через доверенный внутренний клиент в режиме получения байтов и затем `local`. Распаковка поддерживает ZIP, TAR и TAR.GZ. Лимиты на вход — 32 МиБ, на развёрнутые данные — 96 МиБ, на один файл — 24 МиБ, на архив — 5000 записей. Ссылки, специальные файлы и неоднозначные пути приводят к остановке. Сохранённые пути `tree` и `archive` находятся в одном временном каталоге. Разместить отчёт рядом с ними, за пределами `tree`.

## Что сопоставить с артефактом

| Экосистема | Установить идентичность и состав | Прочитать как данные |
| --- | --- | --- |
| npm, yarn, pnpm | Имя с реальным scope и alias, точная версия, источник и integrity, `package/package.json` внутри tarball, optional/peer и платформенные зависимости. | install-хуки, `bin`, `main`/`exports`, `binding.gyp`, включённые в поставку зависимости. |
| PyPI | Имя дистрибутива отдельно от имени импорта, версия, конкретный wheel или sdist. Проверить `Name`, `Version`, `Requires-Dist`, markers и extras в `.dist-info/METADATA` или `PKG-INFO`. Для динамических полей sdist обозначить пробел. | `.pth`, `entry_points.txt`, импортируемые модули, нативные расширения. Для sdist — `pyproject.toml`, build backend, `setup.py` и зависимости сборки. Wheel и sdist оценивать раздельно. |
| NuGet | Источник с учётом сопоставления пакетов реестрам, ID, точная версия, целевые TFM/RID, `.nuspec`, `packages.lock.json`. Сверить подходящим для источника способом подпись или контрольную сумму поставки. | `build`, `buildTransitive`, `.props`/`.targets`, analyzers/source generators, `runtimes` и DLL. Поведение непросмотренной DLL вынести в пробелы. |
| Go | Реальный путь модуля, версия или pseudo-version, `go.mod` и `replace`, доверенный профиль сборки. `h1:` из `go.sum` — хеш содержимого по алгоритму Go. Проверять его доверенным инструментом Go. Для `local --expect` отдельно нужен хеш точных байтов архива. | `init`, выбранные build tags, платформенные файлы, cgo. `go generate` учитывать, если его вызывает процесс команды. |
| Cargo, Composer | Сверить координаты, реестр, выбранный файл, `Cargo.lock`/`composer.lock` и источник зависимостей. Для Git или path использовать соответствующее происхождение. | Rust — `build.rs` и procedural macros. Composer — плагины, `autoload.files` и события, запускаемые корневым проектом. |

Для других экосистем применить ту же процедуру с их доверенным реестром, манифестом и точками запуска. Отразить фактически доступный охват языка и формата. Для VCS-зависимости проверить полный commit и состав именно используемого дерева, подмодулей и поставки. Не переносить вывод с одноимённого публичного пакета на Git, зеркало или внутренний источник.
